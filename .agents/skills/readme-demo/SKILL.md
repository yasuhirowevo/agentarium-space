# README デモ更新

このスキルのファイルを変更する前に、SKILL.mdと同じディレクトリのCONSTITUTION.mdを全文読み、その内容に従うこと。

実行時も最初に [CONSTITUTION.md](CONSTITUTION.md) を読み、依頼が撮影のみか、README 更新・GitHub 掲載まで含むかを確認する。既に承認された範囲は再確認せず進める。以下のパスとコマンドは、特記がなければリポジトリルートを基準にする。

## 1. 更新対象を把握する

- ルートの [AGENTS.md](../../../AGENTS.md)、[PHILOSOPHY.md](../../../PHILOSOPHY.md)、[DESIGN.md](../../../DESIGN.md) の関連仕様、両 README、[撮影手順](../../../docs/demo.md)、`package.json` を読む。
- 作業ツリーと、依頼で指定された PR があればその状態・head branch・現在の本文を確認する。別の作業の差分を巻き込まない。
- 今回見せたい UI・機能と現行デモを比較する。更新の要否だけを聞かれ、見た目や紹介内容が変わっていなければ再撮影不要と回答する。明示された再撮影依頼は実行する。

## 2. 既存の撮影処理を使う

| ファイル | 役割 |
|---|---|
| `scripts/demo-fixture.mjs` | 架空の指示・プロジェクト・セッションと時系列 |
| `scripts/capture-demo.mjs` | 専用の一時領域・Electron 起動・後片付け |
| `scripts/record-demo.mjs` | 両ログルートの指定・描画・録画・配信データ監査 |
| `test/demo-fixture.test.js` | 実際の watcher を通したシナリオ検証 |

スクリプトを読んで、最新の UI・ログ形式でも紹介したい動作が再生できるか確認する。必要な場合だけシナリオや撮影操作を修正する。セッション名・ID・パスを変える場合は、録画側の選択操作・監査条件・テストも整合させる。仕様変更は DESIGN.md を先に更新する。

撮影は両 watcher root と専用プロファイルが一時領域に限定された既存経路で行う。通常起動したアプリやデスクトップ全体の録画で代用しない。撮影のために本体 UI の数値・表示を差し替えず、必要な本体修正は依頼範囲を確認する。

依存関係、FFmpeg と `libx264` の利用可否を確認する。セットアップは撮影手順とルートの指示に従い、不足があれば必要なコマンドを示す。`FFMPEG_PATH` を使う場合は、その実行ファイルで検証する。

```sh
pnpm test -- test/demo-fixture.test.js
pnpm run demo:capture
```

既存の `dist/demo/` に必要な未公開成果物があれば、上書き前に別名で保存する。撮影が失敗・中断した場合、古いファイルや途中出力を成果物として扱わない。原因を確認してから再実行する。

静止画だけの依頼でも、現行コマンドは MP4・PNG・snapshot を同時生成する。MP4 はローカルの中間成果物として扱い、検査は PNG と表示元データに絞って、PNG だけを納品する。動画の生成自体を禁止された場合はこのコマンドを使わず、隔離済みの撮影経路を再利用して静止画だけを取得する。

## 3. 公開するファイルを検査する

撮影コマンドの成功と、今回生成されたファイルのうち納品・公開対象および監査データを確認する。寸法・秒数・フレーム数などは現在のスクリプトと実測値を照合し、以前の撮影値を転記しない。以下の動画検査は動画を納品・公開する場合に行う。

| ファイル | 確認内容 |
|---|---|
| `dist/demo/agentarium-space-demo.mp4` | 動作・可読性・再生・形式・メタデータ |
| `dist/demo/agentarium-space-demo.png` | 構図・文字・映り込み・メタデータ |
| `dist/demo/snapshots.json` | 全配信分の表示データ |

```sh
ffprobe -v error -show_streams -show_format -of json dist/demo/agentarium-space-demo.mp4
ffmpeg -v error -i dist/demo/agentarium-space-demo.mp4 -f null -
```

- 静止画と動画の全期間を確認する。全編再生または全期間をカバーするフレーム一覧を使い、文字や切替箇所が判読できなければ該当フレームを原寸で確認する。デコード成功だけで目視確認を代用しない。
- 入力シナリオと全 snapshot を読み、セッション・指示・パス・ツール出力が架空データ由来であることを確認する。ホームディレクトリ・実プロジェクト・一時領域のパス、機微情報が表示されていないことを点検する。
- snapshot 監査では内部識別用の `session.key` が除外される。UI 更新でこれが画面へ表示されるようになっていないか確認する。監査を通すために表示データを除外しない。
- MP4 の音声ストリームがないこと、コンテナ・ストリームのタグと PNG のテキスト・EXIF 等に個人情報がないことを確認する。疑わしいデータがあれば公開を止め、架空の入力へ直して再撮影する。
- プロジェクトで必要な検証を行う。`pnpm run scan` / `pnpm run web` を実ログで確認した場合、その出力や画面は公開用素材と分けて扱う。

撮影のみの依頼なら、検査済みのローカル成果物と検証結果を渡して完了する。

## 4. 掲載内容を更新する

README 更新・公開が依頼範囲に含まれる場合に進める。PNG を `docs/media/agentarium-space-demo.png` に反映し、MP4 と監査ファイルは ignored の `dist/demo/` に置く。

GitHub 添付には `gh` を使う。現在の `gh pr create --help` / `gh pr edit --help` で `--attach` の対応を確認する。既存 PR なら最新の本文を読んだうえで `gh pr edit <PR> --attach dist/demo/agentarium-space-demo.mp4` により追加できる。新規 PR が必要なら Draft で作り、`--body-file` と `--attach` を使う。対象リポジトリ・PR は今回の依頼から特定し、過去の PR 番号を固定しない。

添付後に PR 本文を読み、実際に返された動画 URL を取得する。添付操作が失敗した場合も、部分成功の可能性があるため現在の本文を確認してから再試行する。

`README.md` と `README.ja.md` の画像リンク・動画リンクを同じ新 URL に更新し、架空データの注記を保持する。GitHub でプレーヤーになるか、静止画になるかは実際の表示で確認する。MP4 を GIF と呼ばず、再生や自動ループの挙動を推測しない。

既存 PR の説明を更新する際は、直前に本文を再取得し、既存添付・ユーザー追記を保持して今回の変更だけを反映する。PR 本文は英語で書く。マージやリリースは今回の依頼に含まれる場合だけ行う。

## 5. 完了を確認する

- 差分とステージ対象を確認し、MP4・snapshot・実ログ・個人環境の情報・無関係な差分がコミットに含まれないことを確かめる。
- プロジェクトのレビュー指示に従う。撮影処理を変えた場合は、対応するテストと再撮影で確認する。
- GitHub 上の変更ブランチで両 README の表示・リンクを確認し、新動画を最後まで再生する。公開を依頼されたのに確認できない場合は、未確認事項として報告する。
- 成果物、PR、実測した動画情報、検証結果、未完了事項を報告する。Draft の状態と main への反映を区別する。
